# v1.4.0

这一版没有加新的界面大功能，重心是**把同步做对**、**把已经发出去但只有半截的功能补完**，以及**修掉一批看得见的毛病**。

三端：手机 `versionCode 14 / versionName 1.4.0`，桌面 `1.4.0`，后端 `app.version.latest = 1.4.0`。

## 同步：从「每次全量」到「按水位增量」

以前两端每次保存都会把整本账推上去，拉取则硬编 `since = 0`——真的开始自动同步后，这会变成每次记账都上传全部历史。

- **两个水位分开存**：`last_sync`（服务端时钟，管 pull）和 `push_watermark`（本机 `last_modified` 时钟，管 push）。两个时钟域混用一个值会互相带偏，所以分成两列。
- **游标不再混用 ID 空间**：原来的游标是 `(lastModified, id)`，`id` 取自流水，却被六张表共用。改成 `SyncCursor`，六个实体各带一对游标，服务端按各自的段查询。客户端一直把游标当不透明字符串透传，所以两端**不需要改协议**。
- **拉取窗口只作用于流水**：`since == 0` 时的「只取近 90 天」以前会连带把分类、账户、模板、预算一起截断。新设备因此拿不到三个月前建、之后没改过的分类。现在窗口只管流水，字典类（含预算）一律全量。
- **`sql/init.sql` 补上 `recurring_rule` 建表**：v1.2.0 加了周期记账，实体和查询都在，但初始化脚本没有这张表，全新 MySQL 库第一次 push 就会失败。
- **写入后触发同步**：两端 14 处写入点（记一笔、删一笔、改预算、改分类/账户、模板、周期规则…）之后都会触发一次同步。此前删掉的流水，墓碑只留在本机，另一端下次拉取仍会拿到那条活记录。
- **桌面端模板补 LWW 比较**：两端各改同一条模板时，`lastModified` 较早的一方不会再胜出。

## 补完的功能

- **编辑已保存的流水（两端）**：以前只能删了重记。现在手机端点历史记录、桌面端双击列表都能进编辑，保存时**保持 `clientId` 不变**，只更新 `lastModified`。报表、预算进度、账户余额随之更新，同步到另一端是同一条被改过，不会多出一条。
- **模板（两端）**：`template` 表和多端同步早就有了，但界面上没有入口。记账页现在是「模板」按钮：列出已保存模板，点选预填金额/分类/账户/备注，也能把当前填的内容存成模板、删除模板。
- **账户余额与净资产（两端）**：`initial_balance` 一直有列、会同步，却没有地方算。现在手机端账户管理里逐账户显示余额，两端报表/仪表盘都显示净资产。口径写死在两端 `AccountBalance` 类的注释里：`余额 = 初始余额 + Σ收入 − Σ支出`（排除已删除，只算 `date <= 今天`）。
- **删除确认（手机端）**：历史记录的删除按钮以前直接生效，现在先弹确认。
- **分类/账户重命名（手机端）**：点按后给出「重命名 / 删除」两个选项。以前拼错名字只能删了重建，而删分类会让旧流水变成「未分类」。

## 安全

- **共享密钥鉴权**：后端加了 `OncePerRequestFilter` 校验 `X-Sync-Token`，放行 `/api/health`。
- **过渡策略**：密钥为空时**不校验**。所以升级顺序必须是「先部署后端（留空）→ 两端填上同一个密钥 → 后端再配密钥」，否则升级那一瞬间旧客户端全部 401。
- **注意**：`/api/version` 也在 `/api/**` 下，配了密钥之后「检查更新」也需要带 token。

## 删掉的东西

- **照片附件整条移除**：`photoPath` 三端都有列、会持久化、会同步，`PhotoController` 提供了上传接口，但全仓库没有任何地方调用它——一个从没被用过的功能。已从实体、DTO、表结构、备份载荷、同步载荷里全部删除。旧数据里那一列只是被忽略，不会出错。

## 看得见的修复

- **环形图配色重做 + 相邻扇区撞色**：原调色板只有 6 色，第 7 块会取回第 1 块的颜色，而环是首尾相接的，于是最大和最小两块并排同色。现在 8 色，且保证相邻（含首尾）不同色。配色也换了一组低饱和同伴色相——原先直接拿「红=支出、绿=收入、灰=禁用」这些语义色当分类色，压在扇区上既打架又显脏。
- **环外引线穿过别的标签**：同侧以前每条标签各算各的折点，竖段正好横穿另一条文字。现在同侧只留一条引线走廊，文字一律在走廊外侧，引线不再交叉。
- **记账日期可选**：点日期那一行弹出日期选择器，可以补记前一天。以前保存时硬写今天，补记的账会落到第二天，总账金额不变但日均和标准差会算歪。不允许选未来。
- **记账页四个按钮一高一矮**：填充按钮和描边按钮的 Material 默认上下 inset 不一样（6dp / 0dp），同一行混排就会一高一矮，「语音输入」「截图记账」还被挤成两行。现在统一 inset、统一高度、单行文字。报表页「AI 消费分析 / 设置」那排是同一个问题，一并修了。
- **报表页顶部数字不跟月份走**：点跨月趋势的柱子只换了环形图，顶部「本月收入/支出/结余」还是当月，标题还写着「本月」。现在数字、环比、标题一起跟着走。
- **记完账切回报表页不刷新**：报表页常驻不重建，切回来只重绘了三张图，顶部数字、预算、热力图都停在进页面时的值。
- **套用模板后分类丢失**：模板一直存着分类，但重建分类栏时无条件清空了当前选择，刚套上的分类立刻被抹掉，还得手选一次。
- **「AI 设置」弹窗滚不动**：说明文字很长，表单排在它下面且自己不滚，小屏上「接口地址/模型」够不到。现在整块内容一起滚。

## 桌面端仪表盘

- 卡片数字被省略号截断：改成自动换行排布，卡片有最小宽度，金额整额显示。
- 点其他月份后卡片不跟着变：现在卡片跟着选中月份走，标题也从「本月」变成「9月」。
- 反复点柱子，提示标签越堆越多：tooltip 改成复用同一个实例。
- 饼图两种形态：长标题把图例挤出可用高度导致「有的有图例、有的没有」。现在统一不设图表标题、关闭图例，月份信息放在面板标题上。
- 饼图看不到具体金额：右侧新增一列数值表，按金额从大到小列出「分类 · ¥金额 · 占比」。

## 版本可追溯

- 每次出包递增 `versionCode`，并把**构建时间**和**提交号**写进 `BuildConfig`。设置页直接显示，装完能一眼分辨装的是哪个构建。这一版起 `versionCode` 是 **14**，桌面端 `BuildInfo` 同样带构建信息。

## 已知未覆盖

- 真实 MySQL 的端到端同步没有跑过，只在 H2 的 MySQL 兼容模式下用 `init.sql` 建库验证。
- 换设备时 `since = 0` 只拉最近 90 天流水（字典类是全量）。更早的历史要靠后端已有数据的完整备份。
- 桌面端分类只有「新建 / 删除」，没有重命名。
- 桌面端饼图分类超过 8 个仍会绕回第 1 个颜色（JavaFX 只有 `default-color0..7`）。
- 手机端窄屏下的按钮排布没能在模拟器上验证（模拟器是副屏自由窗口，改分辨率不重新测量）。
