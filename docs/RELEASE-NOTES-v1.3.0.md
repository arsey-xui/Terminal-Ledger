# v1.3.0

个人双端同步记账系统 —— **离线优先、双端同步**（Android 手机端 + JavaFX 电脑端 + Spring Boot 云端同步服务）。

本次是**功能与观感并重的版本**：重点是把「AI 消费分析」做成两端可用、离线能降级的完整能力
（含自定义提示词与截图识别），并系统性地补齐深色模式、交互动效与图表可读性。

## 本次更新（v1.3.0）

### 新增：AI 消费分析（两端 + 后端）

在报表页点「AI 消费分析」，生成一段关于本月消费的文字分析。

- **双引擎，离线可用**：没配 API Key 时用**本地规则引擎**，完全离线、不出网、
  立刻出结果；配了 Key（OpenAI 兼容接口）则改用大模型增强，结论更细。
  两条路径的输出结构一致，界面上只体现「规则引擎」或「模型」的来源标注。
- **三个按天统计的口径**：分析里给出**本月日平均支出、日支出标准差、日支出中位数**。
  注意口径是**按天聚合后再统计，不是按每一笔**：先把本月每一天的支出加总，
  得到一串「每日支出」，再对这一天序列取平均、标准差、中位数。
  这样「某天集中消费」不会被当成多笔小额。
  - 标准差反映消费的**波动程度**：数值大说明这个月花得不均匀（有大额集中支出）。
  - 中位数不受极端值影响：明显低于平均值时，说明少数几天拉高了整体。
- **自定义提示词（两端都有入口）**：默认提示词已内置，可改成自己的分析口径
  （例如「只关注餐饮和交通」「用更简短的语气」）。留空即恢复默认。
  手机端在「设置 → AI 设置」，电脑端在报表页的「AI 设置」。
  自定义内容随请求下发，**本地规则引擎不受它影响**。
- **截图记账的字段识别（多模态）**：把账单/支付截图里的金额、分类、账户、备注、日期识别出来填进表单。
  图片会压缩后再上传（控制体积与成本），识别结果落到表单字段，**保存与否仍由你决定**。
- **Key 的安全存储**：手机端用 Android Keystore 加密后落盘（`SecretCrypto` / `SecretStore`），
  不以明文写在配置文件里。

详见 [docs/AI-ANALYSIS.md](AI-ANALYSIS.md)。

### 新增：语音记账与桌面小组件（手机端）

- **语音输入**：在记账页点「语音输入」，按「金额 + 分类 + 备注」的口语说法录入，
  解析后回填表单。支持常见的口语量与「块/元」混说。
- **快捷记账小组件**：桌面小组件点一下直接进入快速记账，不必先打开应用再切页面。

详见 [docs/VOICE-AND-WIDGET.md](VOICE-AND-WIDGET.md)。

### 新增：深色模式（两端）

按「近黑、跟随系统」的取向做了完整的深色配色，而不是简单反色。

- **手机端**：`values-night` 一套完整资源（配色、主题、饼图调色板）；
  应用内可在「跟随系统 / 浅色 / 深色」之间切换。
- **电脑端**：`app.css` 提供深浅两套，跟随系统。
- **图表配色与深色底适配**：
  - 饼图调色板按亮度排序，深浅两套各自保证相邻扇区有足够对比；
  - 环形图的洞与「透明圆」默认是库写死的纯白，深色下会变成一个白圆 ——
    改成跟随页面底色（且必须在装上自定义渲染器**之后**设置，否则作用在旧的渲染器上）；
  - 扇区标签的**横线/文字颜色按扇区实际亮度自动选**（用 WCAG 对比度比较两个候选色，
    取对比度更高的那个），而不是按固定亮度阈值判断 —— 旧口径在中间灰上是错的。
- **对话框、日期选择器、状态栏图标**一并适配，不再出现「深色界面里蹦出一个白框」。

详见 [docs/DARK-MODE.md](DARK-MODE.md)。

### 改进：图表可读性

- **环形图标签避让**：外围标签原先会互相重叠（住房/购物这类相邻小扇区的金额被压住看不见）。
  现在先收集所有标签、按上下两侧分别排布再绘制，重叠时自动让位；数值上验证过留出间隔。
- **图例与占位文案**：标签已含金额与分类名，图例冗余则隐藏；无数据时的占位支持多行文案。
- **网格线统一**：坐标轴网格收成 1px 细线，与「酸橙绿 + 直角 + 细线」这套语言一致，
  不再用库默认的虚线灰网格。

### 改进：交互动效（两端）

按「机械、利落、可预期」的取向做，不做弹性回弹和柔和缓动。

| 交互 | 手机端 | 电脑端 |
| --- | --- | --- |
| 按钮按下 | 填充瞬时反转（黑底 + 酸橙绿字）+ 下沉缩放 | 按下深色底 + 酸橙绿字；悬停白底 + 1px 酸橙绿描边 |
| 底部导航 | 指示条平移 180ms；按压压暗 160ms；选中脉冲 180ms | 选中态填充 + 左侧刻度；悬停给 1px 刻度作预告 |
| 页面切换 | **推拉式**：新旧两页并排位移，方向由标签索引增减决定 | 内容淡入 + 自右 14px 滑入，280ms |
| 图表生长 | 按数据扫开 / 从底部升起，800ms | — |

- **去掉了 Material 的圆形水波纹**：它是圆形扩散、缓动柔和，与直角工业语言不搭。
  按压反馈改由「填充反转 + 图标脉冲」承担，信息没有丢失。
- **页面推拉的方向语义**：往右切（选中更靠右的标签）时旧页向左推出、新页自右推入；
  往左切反过来。重复点击同一个标签不再重放动画。
- **图表生长动画为什么是 800ms**：其余动效都在 200~300ms，但这个值不能照搬 ——
  页面位移有明确的参照，眼睛对位移敏感；环形图扫开是覆盖整块画布的连续变化，
  时长太短会被看成「一下就位」。实测 280ms 基本观察不到、600ms 能辨认，取 800ms 留余量。

### 改进：空状态与首次使用

- 四个界面（报表、流水、预算、记账）都有明确的空状态说明，不再是一片空白。
- 记账页在**一笔流水都没有时**显示引导卡片（首次使用）；一旦有数据就收起。
- 分类栏为空时给出提示文案。

### 修复

- **修复（后端）：`LocalDateTime` 反序列化失败。** 手机端写入的是 ISO 字符串，
  而部分旧数据是毫秒时间戳，严格解析会直接抛异常。改为宽松反序列化器
  （`LenientLocalDateTimeDeserializer`），两种格式都接受。
- **修复（手机端）：本地库索引缺失。** 数据库版本 `1 → 3`：`2` 新增周期记账两张表，
  `3` 增补 `idx_txn_cat_date`、`idx_txn_acct_date`，报表按分类/账户聚合不再全表扫描。
  升级按 `oldVersion` 增量执行，既有数据保留。
- **修复（两端）：同步时间字段格式不统一**，导致同一笔记录在两端的表现不一致。
  统一为毫秒时间戳口径，并在文档里写明
  （见 [docs/SYNC-PROTOCOL.md](SYNC-PROTOCOL.md) 的「时间字段的格式要求」）。
- **修复（两端）：周期记账跨设备重复。** 规则随同步下发，待确认项只存本机。
- **修复（电脑端）：导出/备份的加密与校验**，`BackupService` 与 `BackupCrypto` 对齐手机端口径。

### 内部改进（不直接影响使用）

- 后端新增 `ExpenseStats` 统计服务，与手机端、电脑端共用同一套口径
  （三端各有一份实现，避免统计结果不一致）——这是「日平均/标准差/中位数」在三个端上数值一致的前提。
- 新增 `Timestamps`、`SyncStatus` 等工具类，统一时间与同步状态的处理。
- 补齐三端测试：后端 19 项、电脑端 22 项、手机端构建通过。

## 升级提示

- 手机端：`versionCode` 已递增到 `5`，可直接覆盖安装（不会清数据）；也可在应用内「设置 → 检查更新」升级。
- 电脑端：下载新的免安装包解压替换即可 —— 数据存放在用户目录 `~/accounting`
  （H2 数据库与配置），**不会因替换程序而丢失**。
  > 若从本仓库的 `outputs\` 目录直接运行，该目录带 Low 完整性标签可能让数据库变成只读，
  > 处理办法见 [docs/BUILD-AND-RELEASE.md](BUILD-AND-RELEASE.md)。
- 数据库结构：手机端本地库 `1 → 3`（`2` 新增周期记账两张表，`3` 补两个组合索引），
  两段都在 `onUpgrade` 里按 `oldVersion` 增量执行，**保留既有账本数据**；
  电脑端为建表时 `CREATE TABLE IF NOT EXISTS` 自动补表。
- 兼容性：未改动同步协议既有字段，旧版本客户端可继续使用。
