# v1.1.1

个人双端同步记账系统 —— **离线优先、双端同步**（Android 手机端 + JavaFX 电脑端 + Spring Boot 云端同步服务）。

本次是 **1.1.0 的修订版本**：修掉一个会「点重置后分类/账户全没」的严重问题，统一账户初始余额口径，并把环形图标签改回扇区内居中显示。

## 本次更新（v1.1.1）

### 修复

- **修复（手机端）：重置分类 / 重置账户后条目全部消失。**
  重置的第一步是把现有分类、账户软删除（保留行作为同步墓碑），第二步写回内置默认数据时用的却是普通 `INSERT`；默认数据的 `client_id` 是固定的（`cat-food`、`acc-cash` 等），这些行的主键已经存在，于是每条插入都撞主键失败，而 Android 的 `db.insert()` 失败是**静默**的（返回 -1 不抛异常），结果默认数据一条都没回来。
  现已改为 `INSERT ... ON CONFLICT(client_id) DO UPDATE`：已存在的行会被**复活**（`deleted` 置 0、刷新 `last_modified`，从而在 LWW 同步里胜过其它设备上的旧删除墓碑），名称、图标、类型修正为默认值，`created_at` 保留；用户自建的分类/账户仍保持删除状态。
- **修复（手机端）：默认数据自愈。** 若「未删除的支出分类 / 收入分类 / 账户」一个都不剩（旧版本重置后只剩墓碑的情况），打开应用时会自动补回内置默认数据。旧版本中招的设备**装上 1.1.1 覆盖安装、重开一次即可恢复**，不必再手动点重置。
- **修复（电脑端）：删除分类/账户后重启会被当成首次安装。** 「表是否为空」的判定改为只统计未删除（`deleted=0`）的行，避免用户把分类或账户删完后重启又被灌一遍默认数据。

### 改进

- **环形图标签回到扇区内居中显示（两端统一口径）。** 每个扇区正中两行水平居中：第一行**金额（黑字加粗，带「元」）**，第二行**分类名（白字，带淡淡描边以适配浅色扇区）**；不再外移、不再引线、不显示占比。扇区较窄时会按扇区可用宽度自动缩字号（有下限），保证文字压在扇区内不被中心洞或外缘裁掉；只有极窄扇区（约 1–2%）才用引线放到环外兜底。
- **账户初始余额口径统一（电脑端）。** 「重置账户」恢复默认账户时**保留原有的初始余额**，只把名称、图标、类型修正回默认值；移动端本来就是保留，现在两端一致。
- **重置提示更明确（手机端）。** 重置确认框会列出将要恢复的默认清单，完成后 Toast 提示「已恢复 10 个支出分类、4 个收入分类」「已恢复 5 个默认账户」。

### 默认数据清单（两端一致）

- 支出分类：餐饮、交通、购物、住房、通讯、医疗、教育、娱乐、人情、其他
- 收入分类：工资、副业、红包、其他收入
- 默认账户：现金、储蓄卡、信用卡、微信、支付宝

## 升级提示

- 手机端：`versionCode` 已递增到 `3`，可直接覆盖安装（不会清数据）；也可在应用内「设置 → 检查更新」升级。
- 电脑端：下载新的免安装包解压替换即可 —— 数据存放在用户目录 `~/accounting`（H2 数据库与配置），**不会因替换程序而丢失**。
- 本次未改动同步协议与数据库表结构，可与 1.1.0 客户端混用。
