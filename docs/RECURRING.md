# 周期记账（自动续费 / 固定收支）

解决「每月手动录一遍房租、会员、月供」的问题：**先建规则，到期后生成待确认项，确认（可改金额）才真正入账**。
手机端与电脑端口径完全一致，规则本身会通过同步接口跨设备共享。

## 使用方式

| 端 | 入口 | 说明 |
| --- | --- | --- |
| 手机端 | 设置 → 周期记账 | 待确认清单 + 规则列表，可新建/编辑/删除规则 |
| 手机端 | 记账页顶部提示 | 有待确认项时显示「有 N 笔周期记账待确认」 |
| 电脑端 | 左侧导航「周期记账」 | 待确认清单 + 规则列表；侧边栏会显示待确认数量 |

规则字段：名称、金额、类型（支出/收入）、分类、账户、备注、**间隔（每 N 天 / 周 / 月）**、首次日期。

## 到期日怎么算

三种单位，都从「首次日期」往后推：

- **每天/每 N 天**：`首次日期 + N 天`。想表达「每 30 天续费一次」就填 `30 天`。
- **每周/每 N 周**：`首次日期 + N 周`（同星期几）。
- **每月/每 N 个月**：按首次日期的「日」重复；**当月没有该日时自动取月末**
  （例如首次日期 31 日：2 月记 28/29 日，4 月记 30 日）。

规则从上一次生成日期之后继续推算到「今天」，所以：

- 到期日还没到 → 不生成任何东西；
- 到期日已过且从未生成 → 会补生成这些期数（首次日期填得早就会补出多期），不想要的期可以直接「忽略本期」；
- 应用每次启动（手机端）／每次启动或进入周期记账页（电脑端）都会推进一次，**幂等**，不会重复生成。

## 待确认项与入账

- 每期待确认项都有一个**确定 ID**：`rr-<规则ID前8位>-<yyyyMMdd>`。
- 点「确认入账」时，就用这个 ID 写入一条流水（`source = RECURRING`），并把待确认项标记为 `ACCEPTED`；
  「忽略本期」标记为 `SKIPPED`，两者都不会再出现在待确认清单里。
- 因为 ID 是确定的，**两台设备各自确认同一期，同步后也只会是同一条流水**（LWW 合并），不会重复入账。
- 续费涨价时用「改金额后确认」，只影响这一期，规则金额不变。

## 数据与同步

| 数据 | 存放 | 是否同步 |
| --- | --- | --- |
| 规则 `recurring_rule` | 手机 SQLite / 电脑 H2 / 云端 `recurring_rule` 表 | 是（LWW + 软删除墓碑） |
| 待确认项 `recurring_pending` | 仅本机 | 否（确认后生成的流水才同步） |

同步接口沿用现有协议，`/api/sync/push` 与 `/api/sync/pull` 各增加一个 `recurringRules[]` 字段，
元素字段与其它实体同构（`clientId` / `lastModified` / `deleted` + 业务字段）。
因此**不启动后端也能用**：规则与待确认项都在本地，只有跨设备共享规则时才需要后端。

## 删除规则

删除规则是软删除（同步到其它设备），同时清掉它**尚未确认**的待确认项；已经入账的流水不受影响。
